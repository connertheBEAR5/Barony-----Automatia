4. DEMONSTRATED BUGS AND FIXES
==============================

1. party_cross_map_live_probe hard-coded persistence schema version 2. Current
   saves use schema 3, so a valid restarted server was falsely rejected. The
   probe now parses JSON and compares against
   AutomatiaSave::CURRENT_SCHEMA_VERSION while validating map_instance scope,
   one map, party state and sam_fingerprint.

2. late_join_live_probe accepted STRT only through version 4 and assumed the
   old 24-byte position. The current server sends version 5 with a 36-byte
   position containing playableFloor and spatialRevision. The probe now decodes
   and reports those fields; the contained late join then passed.

3. Persistent-world restore diagnostics supplied the mechanism counters in an
   order different from the log labels. Restoration state was correct, but a
   chest could be reported as a campfire/wall-lock/other mechanism. The argument
   order now matches the labels.

4. Zed/LMP concrete item fields reserve 0 for none and 1 for random, so they
   store a concrete runtime item ID as runtime ID + 2. The initial authored
   S.A.M metadata path treated those fields as raw IDs. A custom ground item or
   Mini Mimic equipment slot could consequently resolve two IDs low during map
   activation. Editor entry/display, templates, SMID save/load and runtime
   activation now consistently decode/encode that existing representation.
   Stable identity remains authoritative; when the stable definition is absent,
   a ground item is omitted and a monster slot becomes empty instead of being
   reinterpreted as unrelated content.

5. Duplicate S.A.M room declarations with the same namespace/path were formerly
   de-duplicated after an absolute-path tie-break. Different installation roots
   could therefore choose different bytes. The effective room set now sorts
   duplicate logical keys by byte digest before any path tie-break, and the
   generation pool and SAMF catalog are built from that same selection.

No speculative production redesign was made. No demonstrated state corruption,
cross-MapInstance alias or S.A.M inventory duplication remained in the exercised
paths.
