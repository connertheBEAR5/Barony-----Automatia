QUEST JOURNAL BACKEND
=====================

Purpose
-------
This milestone prepares the data layer for an inventory quest-journal
tab. It does not draw the UI yet.

Public API
----------
getCustomDialogueQuestJournalEntries(player, entries)

The function returns journal-ready entries for the selected player.

Quest entry data
----------------
Each entry contains:

- dialogue ID
- quest ID
- title
- summary
- general objective
- completion text
- failure text
- scope
- repeatable flag
- current player-specific stage
- accepted/completed/failed flags
- calculated journal status
- objective list

Journal statuses
----------------
Active
Completed
Failed

Unstarted quests are omitted.

Objective data
--------------
Each objective contains:

- objective ID
- active text
- completed text
- authored stage
- optional flag
- player-specific completion flag
- visibility flag

An objective is visible when:

- its authored stage is at or below the player's current quest stage, or
- the player already completed it

Sorting
-------
Quest entries sort in this order:

1. Active
2. Completed
3. Failed

Entries within a status sort by title.

Objectives sort by:

1. Stage
2. Required before optional
3. Text

Discovery limitation
--------------------
The backend enumerates valid custom-dialogue definitions already loaded
into the active process. Therefore a quest becomes journal-discoverable
after its dialogue definition has been loaded, normally when its NPC is
first interacted with.

A future quest manifest can preload every authored quest definition.
