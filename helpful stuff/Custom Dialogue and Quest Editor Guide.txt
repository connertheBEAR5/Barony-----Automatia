BARONY CUSTOM DIALOGUE AND QUEST EDITOR GUIDE
=============================================

This is the single maintained guide for the custom dialogue/quest
system. Future packages update this file instead of adding a new
documentation file for every code change.


1. FILE LOCATION AND DIALOGUE IDS
=================================

Dialogue JSON files are stored in:

    dialogue/<dialogue_file_id>.json

The Custom Dialogue ID entered on an NPC sprite chooses the filename
directly.

Example:

    NPC Custom Dialogue ID: village_guard
    Loaded file: dialogue/village_guard.json

The game does not scan every JSON file looking for a quest ID.

Dialogue/File ID and Quest ID are separate:

    Dialogue/File ID
        Controls the JSON filename and the NPC's Custom Dialogue ID.

    Quest ID
        Controls persistent quest progress, journal identity,
        conditions, objectives, completion, and failure state.

Example:

    Dialogue/File ID: village_guard
    JSON filename:    village_guard.json
    Quest ID:         convince_the_guard


2. OPENING THE EDITOR
=====================

Open an NPC's sprite properties and use the custom-dialogue EDIT button.

The editor has four separate columns:

    JSON Files:
        The far-left file list. Keeping it separate prevents filenames
        from overlapping buttons.

    Toolbox:
        Vertical paired controls immediately to the right of the file
        list.

    Decision Tree:
        Dialogue nodes, choices, and next-node links.

    Quest / Node Details:
        Quest metadata, selected node details, conditions, and actions.


3. VERTICAL TOOLBOX
===================

File controls:

    NEW
        Creates a new valid dialogue JSON file.

    SAVE
        Writes the current in-memory JSON document.

    RELOAD
        Discards the current in-memory copy and reloads the selected
        JSON file.

    RENAME
        Renames the selected JSON file when Dialogue/File ID is the
        active editable field.

        It:
        - normalizes the new filename,
        - refuses blank names,
        - refuses overwriting another JSON,
        - keeps the renamed file selected,
        - updates the selected NPC's Custom Dialogue ID,
        - does not change quest_id.


Node and choice controls:

    +NODE / -NODE
        Add or safely remove dialogue nodes.

        A node cannot be removed when:
        - it is the start node,
        - it is the only remaining node,
        - another node links to it,
        - a choice links to it.

    +CHOICE / -CHOICE
        Add or remove choices on the selected node.

    NEXT>
        Cycles the selected choice's destination through existing
        nodes.

    ONCE
        Toggles whether the selected choice can only be used once.


Objective controls:

    +OBJECT / -OBJECT
        Add or remove quest objectives.

    OPTIONAL
        Toggles the selected objective between required and optional.

    OBJ MARK
        Toggles a static minimap marker for the selected objective.


Field controls:

    CAT< / CAT>
        Change field category.

    FIELD< / FIELD>
        Move backward or forward inside the current field category.

    EDIT
        Copies the selected field into the text-input buffer.

    APPLY
        Writes the edited value to JSON, saves, and reloads the preview.


Field categories:

    File/Quest
        Dialogue/File ID
        Quest ID
        Quest Title
        Quest Summary

    Text
        Node Text
        Choice ID
        Choice Text

    Objective
        Objective ID
        Objective Text
        Objective Stage
        Objective Target

    Condition
        Condition Reference
        Condition Number

    Action
        Action Number

    Marker
        Marker X
        Marker Y


Condition and action selectors:

    COND TYPE
        Cycles supported choice-condition presets.

    ACTION
        Cycles supported choice-action presets.

    COMPARE
        Cycles:
            equals
            not_equals
            at_least
            at_most

    SCOPE
        Cycles:
            player
            party
            world

        Current runtime limitation:
        Only player scope is currently accepted by the game runtime.

    COND ITEM
        Cycles valid current requirement-item aliases:
            torch
            tool_torch

    REWARD
        Cycles:
            Off
            healing_potion
            torch
            Off

    REMOVE ITEM
        Toggles removal of one torch.

    REMOVE GOLD
        Toggles removal of 100 gold.
        Use Action Number to change the amount.


Other controls:

    RECRUIT
        Toggles action.recruit_npc on the selected choice.

    REPEAT
        Toggles quest.repeatable.

    GIVER MARKER
        Cycles:
            Off
            Static tile
            Follow selected NPC
            Off


4. BASIC JSON FORMAT
====================

A minimal dialogue/quest file:

{
  "version": 1,
  "quest_id": "convince_guard",
  "quest": {
    "title": "Convince the Guard",
    "summary": "Earn the guard's trust.",
    "scope": "player",
    "repeatable": false,
    "objectives": []
  },
  "start_node": 0,
  "nodes": [
    {
      "id": 0,
      "text": "Why should I follow you?",
      "next": 0,
      "choices": []
    }
  ]
}


5. QUEST ORIGIN AND GIVER MARKERS
================================

Static quest-giver marker:

"origin": {
  "label": "Village Guard",
  "map": "village.lmp",
  "x": 12,
  "y": 8
}

Dynamic marker following an NPC:

"origin": {
  "label": "Village Guard",
  "map": "village.lmp",
  "track_npc": true,
  "npc_persistent_id": 125
}

Dynamic behavior:

- The marker follows the live NPC's current tile.
- It only appears while the NPC is on the active origin map.
- It disappears when the NPC is dead or removed.
- It disappears after that NPC becomes a follower.


6. OBJECTIVES

Example objective:

  "target": 1,

    "map": "village.lmp",

    "y": 14
  }

Required fields:

    id
    text

Optional fields:

    completed_text
    stage
    optional
    progress_variable
    target
    map_marker

8. CHOICE CONDITIONS
====================

Has item:

"condition": {
  "type": "has_item",
  "item": "torch",
  "count": 1
}

Has gold:

"condition": {
  "type": "has_gold",
  "amount": 100
}

Quest completed:

"condition": {
  "type": "quest_completed",
  "quest": "prove_yourself"
}

Quest stage:

"condition": {
  "type": "quest_stage",
  "quest": "prove_yourself",
  "stage": 2,
  "comparison": "at_least"
}

Objective state:

"condition": {
  "type": "objective_completed",
  "quest": "prove_yourself",
  "objective": "kill_monster"
}

NPC flag:

"condition": {
  "type": "npc_flag",
  "id": "recruited",
  "value": false
}

Supported comparisons:

    equals
    not_equals
    at_least
    at_most


9. CHOICE ACTIONS
=================

Accept a quest:

"action": {
  "quest_accept": true
}

Complete a quest:

"action": {
  "quest_complete": true
}

Change quest stage:

"action": {
  "quest_stage": 2
}

Reward gold:

"action": {
  "reward_gold": 100
}

Remove gold:

"action": {
  "remove_gold": 100
}

Reward an item:

"action": {
  "reward_item": {
    "item": "healing_potion",
    "count": 1
  }
}

Remove an item:

"action": {
  "remove_item": {
    "item": "torch",
    "count": 1
  }
}

Recruit the NPC:

"action": {
  "recruit_npc": true
}

After successful recruitment, the runtime sets the NPC flag:

    recruited = true


10. CURRENT ITEM LIMITATIONS
============================

The current runtime recognizes these authored item names:

Requirement/removal:

    torch
    tool_torch

Rewards:

    healing_potion
    potion_healing
    torch
    tool_torch

The editor intentionally does not generate unsupported item names.


11. EDITOR WORK STILL PLANNED
=============================

The editor still needs expanded controls for:

- quest start, fail, and reset actions,
- objective complete and clear actions,
- arbitrary reward/remove item counts,
- world/NPC/quest flags and variables,
- remote power actions,
- NPC movement actions,
- node-level conditions,
- direct true/false branch selection,
- direct destination-node selection,
- duplication and reordering,
- delete/duplicate file controls,
- validation panel,
- unsaved-change warning,
- confirmation prompts,
- scrolling details panel,
- improved visual graph layout.



Dynamic column sizing
---------------------
The editor measures current filenames and quest metadata when drawing
the window:

- JSON Files grows for the longest filename.
- Toolbox keeps enough width for paired controls.
- Quest / Node Details grows for longer metadata.
- Decision Tree receives the remaining width.

Columns have minimum and maximum sizes so the complete editor stays
inside the subwindow. Text that is still too long is shortened with
"..." rather than overflowing into another column.



Multiline readability
---------------------
The dialogue editor uses more of the available screen and wraps long
text instead of only clipping it.

- Quest summaries are displayed across multiple lines.
- Selected node text is shown in full in the details panel.
- Selected choice text is shown across multiple lines.
- Decision-tree node and choice labels wrap to several lines.
- Extremely long text remains safely contained inside its panel.

The full JSON value is preserved when editing even when only part of it
fits inside the small toolbox input bar. The right-side details panel is
the readable multiline preview.


PART 12B DIRECT CHOICE AND FILE TOOLS
====================================
EDIT CHOICE
    Select a choice in the decision tree and click EDIT CHOICE. The
    editor immediately switches to Choice Text and starts text input.
    Type the new text and click APPLY.

VALIDATE
    Checks the JSON root, version, start node, node IDs, node text,
    choice fields, and destination links. The first exact problem is
    displayed in the editor status line.

DUP FILE
    Creates a unique copy of the selected dialogue JSON and selects it.

DEL FILE
    Deletes the selected dialogue JSON. Press DEL FILE twice within four
    seconds to confirm.



PART 13: GUIDED ACTION BUILDER
==============================

The old ACTION cycle has been replaced by understandable action groups.

1. Select a choice in the Decision Tree.
2. Use ACTION < or ACTION > to select a group.
3. Click the plainly named action you want.
4. Use the existing editable fields for IDs or numbers that need to be
   changed from their starter values.
5. Press VALIDATE.

Action groups
-------------

Quest:
    START QUEST
    ACCEPT QUEST
    COMPLETE
    FAIL QUEST
    RESET QUEST
    SET STAGE

Rewards:
    GIVE GOLD
    GIVE ITEM

Costs:
    TAKE GOLD
    TAKE ITEM

Objectives:
    FINISH OBJ
    CLEAR OBJ

Flags:
    WORLD FLAG
    NPC FLAG

Variables:
    SET WORLD
    ADD WORLD
    SET NPC
    ADD NPC
    SET QUEST
    ADD QUEST

NPC:
    RECRUIT NPC
    EMPTY ACTION

CLEAR ACTION removes the whole action object from the selected choice.

Starter values
--------------

GIVE GOLD:
    reward_gold = 100

GIVE ITEM:
    healing_potion, count 1

TAKE GOLD:
    remove_gold = 100

TAKE ITEM:
    torch, count 1

SET STAGE:
    quest_stage = 1

FINISH OBJ / CLEAR OBJ:
    Uses the currently selected objective ID when available.
    Otherwise it starts with objective_1.

Flags:
    Start with story_flag or npc_flag set to true.

Variables:
    Start with a clearly named placeholder and value/amount 1.

These are starter values, not hidden permanent values. Edit the numeric
or ID fields after creating the action.

EXAMPLE JSON FILES
==================

The folder:

    helpful stuff/dialogue examples/

contains small working examples. Copy an example into your project's
dialogue folder, rename it, and set an NPC's Custom Dialogue ID to the
filename without .json.

Examples are intentionally limited to fields understood by the current
runtime. The runtime currently accepts quest state actions, item/gold
rewards and costs, objective actions, world/NPC/quest variables, flags,
and recruitment.


PART 14: UNIVERSAL ITEM AND STATUS REWARDS
==========================================

Any item
--------
The Rewards and Costs groups now show ITEM < and ITEM >.

The editor displays:
    Item ID
    identified in-game item name

GIVE ITEM creates a reward using the selected item.
TAKE ITEM creates a cost using the selected item.

The JSON stores the numeric ItemType as a string:

    "reward_item": {
        "item": "42",
        "count": 1
    }

Numeric strings from 0 through NUMITEMS - 1 are accepted. Existing
friendly aliases such as torch and healing_potion remain compatible.

Status effects
--------------
Choose the Status action group.

Controls:
    EFFECT < / EFFECT >
    TIME - / TIME +
    POWER - / POWER +
    APPLY STATUS / CLEAR STATUS

TIME is measured in seconds.
POWER is the effect strength from 1 through 255.

Generated JSON:

    "status_effect": {
        "effect": 5,
        "duration_seconds": 30,
        "strength": 1,
        "enabled": true
    }

CLEAR STATUS writes enabled false and removes the selected effect from
the player.

Important:
Some Barony effects are internal mechanics rather than ordinary player
buffs or debuffs. The system permits all valid effect IDs, but map
authors should test unusual IDs before shipping a map.


PART 14 COMPILE-FIX NOTE
========================
The universal item selector currently displays the selected numeric item
ID rather than reading ItemGeneric's private internal item-name field.

This does not reduce runtime item support. GIVE ITEM and TAKE ITEM still
accept every valid ItemType from 0 through NUMITEMS - 1.

A later UI improvement should resolve names through a confirmed public
ItemGeneric accessor or a separate editor-safe item-name table.


PART 15: QUEST-GIVER BINDING AND ITEM NAMES
===========================================

Quest giver binding
-------------------

Custom Dialogue ID only tells an NPC which JSON file to open. It does
not automatically assign that NPC as the quest giver.

To assign the quest giver:

1. Place the NPC.
2. Save the map so the NPC receives a persistent ID.
3. Select the NPC again.
4. Open the Dialogue and Quest Editor.
5. Open the quest JSON.
6. Click USE SELECTED NPC.

The editor copies the selected NPC's persistent ID and current map into
the quest origin. It also enables track_npc and removes static x/y
coordinates.

CLEAR GIVER removes the dynamic NPC assignment.

The toolbox displays:

    Quest giver ID: 1842

A value of zero means no dynamic quest giver is assigned.

Item-name display
-----------------

The universal item selector now displays both:

    Selected item ID: 42
    Item: identified item name

The name comes from ItemGeneric::getIdentifiedName(), which is the
public accessor used elsewhere in Barony.

The JSON still stores the numeric item ID so every ItemType remains
supported.


Viewing actions already applied
-------------------------------

Select a choice in the Decision Tree.

The right-side details panel now shows:

    Applied actions:
    - Start quest
    - Give item: iron sword x1
    - Complete objective: bring_supplies
    - Set world flag: gate_open

The summary reads every supported field from the selected choice's
action object. Numeric item IDs are converted back to identified item
names.

When an action uses unsupported custom JSON fields, the summary shows:

    Custom action fields


PART 16: GUIDED UI STATUS AND AMOUNT CONTROLS
=============================================

Gold amounts
------------

The Rewards and Costs action groups now show:

    GOLD -10
    GOLD +10
    Gold amount: 100

Set the amount first, then click GIVE GOLD or TAKE GOLD. The amount is
written directly into reward_gold or remove_gold.

Item quantities
---------------

The item selector now shows:

    Selected item ID: 31
    Item: identified item name
    QTY -
    QTY +
    Item quantity: 1

Set the item and quantity before clicking GIVE ITEM or TAKE ITEM.

Named effects
-------------

The Status group now displays:

    Effect 22: Health Regeneration
    Duration: 30s
    Strength: 1

Effect IDs 0 through 134 have readable names taken from the current
Barony effect constants. IDs 135 through 159 are displayed as Reserved /
unnamed.

Choice colors
-------------

The Decision Tree now explains authored behavior beneath each choice:

    Green:
        Requirements and conditions

    Blue:
        Objective complete/clear actions

    Red:
        Actions and rewards

Example:

    -> I brought the torch. [next 2]
       Requires: Requires torch x1
       Objective: Completes bring_torch
       Action: Take item

Condition selection
-------------------

NEXT CONDITION cycles through the supported condition templates. The
current condition is shown immediately below the button.

The details panel lists the available condition families and shows the
selected choice's exact requirement. Use the existing Condition
Reference and Condition Number editable fields to change IDs, item
references, stages, amounts, or variable values.

This is intentionally guided: the editor shows what is selected, what
will be written, and what is already attached to each choice.


PART 17: BUTTON TOOLTIPS AND SAFE STATIC MARKERS
================================================

Hover over any dialogue-editor button. The bottom status line now shows
what that exact control changes. Normal success and error messages still
take priority.

GIVER MARKER no longer writes tile 0,0 when nothing is selected. In that
case the marker is turned off and the editor reports the reason.

Quest-completed checks already exist. Use NEXT CONDITION until Quest
Completed is selected, then set Condition Reference to the other quest's
quest_id.


PART 18: COMBINED GUIDED AUTHORING UPDATE
========================================

This package combines several planned stages.

Static giver markers
--------------------

USE CURSOR TILE writes the current editor cursor tile directly into the
quest origin. The toolbox then displays:

    Static giver tile 24, 17

An invalid/outside cursor turns the marker off rather than writing 0,0.

Dynamic giver markers
---------------------

USE SELECTED NPC copies the selected NPC's persistent ID. The toolbox
then displays:

    Giver follows NPC ID 1842

Condition browser
-----------------

COND < and COND > browse all guided condition templates:

    None
    Has item
    Has gold
    Quest started
    Quest accepted
    Quest completed
    Quest failed
    Quest stage
    Objective completed
    Objective incomplete
    World flag
    NPC flag
    World variable
    NPC variable

CLEAR CONDITION removes only the selected choice requirement. CLEAR
ACTION remains separate.

Quest-completed checks
----------------------

Select Quest Completed with COND < or COND >. Then use the Condition
category's reference field to enter the other quest's quest_id.

The initial templates use the currently selected item, item quantity,
gold amount, quest ID, and objective where applicable.

Restart Game
------------

GameUI.cpp includes the confirmed stale quest-journal frame-pointer fix.
The journal and tracker are re-associated with the newly created UI tree
after Restart Game.


PART 19: GUIDED CONDITION VALUE SELECTORS
=========================================

Has Item requirements
---------------------

After selecting Has Item with COND < or COND >, the toolbox displays:

    REQ ITEM <
    REQ ITEM >
    Required item ID: 42
    Item: iron sword
    REQ QTY -
    REQ QTY +
    Required quantity: 1

Changing the item or quantity immediately updates the selected choice's
condition. The user does not need to type the item ID into JSON.

Quest-state requirements
------------------------

For Quest Started, Quest Accepted, Quest Completed, Quest Failed, and
Quest Stage, the toolbox displays:

    QUEST <
    QUEST >
    Quest ID: village_help
    Title: Help the Village

The editor scans every valid JSON file in ./dialogue, collects unique
quest_id values, and lets the author browse them by title.

Changing the selected quest immediately updates the condition's quest
reference. This works for checking whether any other authored quest is
started, accepted, completed, failed, or at a particular stage.


PART 20: GUIDED CONDITION PARAMETERS
====================================

Has Gold
--------

Use GOLD REQ -10 and GOLD REQ +10 to adjust the required amount. TYPE
EXACT AMOUNT opens the guided number field for a precise value.

Quest Stage
-----------

Choose the required quest with QUEST < and QUEST >. Then use STAGE - and
STAGE + to set the required stage.

Objective Complete / Incomplete
-------------------------------

Use OBJECTIVE < and OBJECTIVE > to browse the current quest's objectives.
The editor displays both objective ID and objective text.

World and NPC flags
-------------------

EDIT FLAG NAME opens a guided text field for the persistent flag ID.
TOGGLE REQUIRED VALUE switches between requiring true and false.

World and NPC variables
-----------------------

EDIT VARIABLE NAME opens the guided variable-ID field. VALUE - and VALUE
+ adjust the required number. COMPARE cycles equals, not-equals,
at-least, and at-most. TYPE EXACT VALUE accepts a precise integer.

These controls update the selected condition immediately and keep the
green requirement summaries synchronized.
