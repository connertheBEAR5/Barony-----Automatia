STATUS LEGEND

  BEHAVIOR VERIFIED
    A deterministic state transition was executed in an isolated test using
    shared runtime decoding/state logic.

  DISPATCH VERIFIED
    The real shared parser accepts the valid form, rejects its catalogued
    invalid form, resolves it to the catalog entry, and the consistency test
    finds the declared active C++ handler seam. Live world mutation remains a
    manual test unless separately stated.

  PARSER VERIFIED
    Parser contract only. There are currently no catalog entries left at this
    level; every insertable entry has at least active-dispatch evidence.

  MANUAL BEHAVIOR REQUIRED
    Parser and dispatch are code-backed, but the gameplay effect has not been
    represented as a deterministic live-world fixture in this pass.

  BLOCKED IN EDITOR TEST MODE
    The tag mutates a live map, player, entity, level, inventory, mechanism, or
    network-relevant state. The Zed tester reports it without executing it.

  UNSUPPORTED / HISTORICAL
    Not accepted as a current canonical runtime tag and not insertable.

  AVAILABLE
    The owning native implementation or extension callback is present. This is
    independent of verification depth; registration alone never upgrades a tag
    to Dispatch or Behavior Verified.

  UNAVAILABLE - MISSING MOD
    Retained extension metadata is visible for diagnosis, but parser validation
    rejects execution and the live callback pointer has been cleared.

  NEEDS VERIFICATION
    A callback may be registered and routable, but its declared grammar/dispatch
    or behavior has not yet earned the corresponding verification level.

same script retain their original order and duplicates and continue executing.
This removes a tester/runtime safety mismatch without making one malformed token
silently suppress every otherwise valid command.


2. END-TO-END CURRENT ARCHITECTURE

2.1 Authored Text Source storage

  * Sprite 132 is the Text Source entity.
  * TextSourceScript::getScriptFromEntity() assembles bytes from skill[4] through
    skill[59], excluding skill[28] because that slot is circuit_status.
  * Four bytes are decoded per nonzero skill word. Empty skill words are skipped,
    so the persisted physical fields are concatenated; authors must provide the
    spacing that should exist between adjacent tags.
  * Inline Text Source storage is bounded by the legacy skill array and 256-byte
    local buffer. Resource scripts are not constrained to that physical field
    capacity, though the Zed editable tester deliberately caps its working copy
    at 16 KiB.

2.2 Resource indirection

  * If the assembled source begins with '$', getScriptFromEntity() calls the
    shared resolveTextSourceResource().
  * The resolver follows the gameplay word convention: space, LF, CR, and NUL
    terminate the key; '$' bytes before the terminator are omitted.
  * ScriptTextParser.allEntries supplies formattedText from /data/scripts.
  * The gameplay resolver historically accepts any found object type. Zed warns
    when an entry is not OBJ_SCRIPT but preserves that behavior.
  * A missing key leaves gameplay with the original '$...' inline string. Zed
    reports the miss and clears its working copy.

2.3 Map-generation recognition and attachment setup

  * TextSourceScript::parseScriptInMapGeneration() retrieves the source.
  * A valid @script marker changes textSourceIsScript from message mode to the
    script lifecycle and initially selects circuit power triggering.
  * @triggerif= configures automatic trigger state.
  * @attachto= and optional @attachrange= build a UID child list once during map
    post-processing.
  * Runtime filtering now excludes candidates on another playableFloor.
  * @reattachto= is different: it clears and rebuilds the UID set at execution
    time, in sequence with surrounding commands.

2.4 Runtime trigger lifecycle

  * Entity::actTextSource() returns immediately on multiplayer CLIENT. Gameplay
    mutation is therefore server/single-player authoritative.
  * Default scripts respond to circuit power.
  * Automatic conditions are always, attached entities removed, attached
    entities existing, all attached invisible, all attached visible, and bell
    interaction/breakage.
  * Trigger satisfaction marks an attached script fired.
  * textSourceDelay counts down while powered. The original delay is retained in
    the upper 16 bits of textSourceVariables4W.
  * The low run-state byte prevents repeat execution while continuously powered.
    A resettable power source can clear it after power is removed unless the
    configured one-shot byte prevents that reset.

2.5 Shared parsing and validation

  * parseTextSourceScript() scans the source for '@'.
  * A token ends on ASCII space, another '@', or NUL. LF, CR, and tab are not
    token separators in the legacy gameplay grammar.
  * Trailing CR/LF is accepted for no-argument/integer forms where the legacy
    decoder can consume it. A tab inside a token is rejected.
  * @attached. is normalized into Token::attached plus the underlying canonical
    command.
  * Literal definitions and registered aliases are resolved from the unified
    scriptTagDefinitions() view. That view contains the immutable native
    catalog followed by deeply owned extension registrations.
  * Stats and proficiencies are resolved by generated-family parsing.
  * Proficiency indices must use the exact runtime-generated decimal spelling;
    leading-zero forms such as @pro01= are rejected because the dispatcher only
    generates @pro1=.
  * Each Token records canonicalTag, catalogIndex, safety, source position, and
    validity.
  * Extension aliases preserve the spelling used in Token::command while
    canonicalTag identifies the owning command definition.
  * Retained missing-mod definitions resolve for diagnostics but produce an
    unavailable error and valid=false; they never reach a stale callback.
  * Registered private argument schemas may supply a validator callback. Shared
    built-in argument kinds continue using the same native parser contracts.
  * Unknown or malformed tokens produce Error diagnostics and valid=false.
  * Prefix misuse produces a Warning when required attachment is missing or when
    @attached. has no target-specific meaning. Prefixing the four map-generation
    directives is an Error because their setup path never strips that prefix.

2.6 Live dispatch

  * TextSourceScript::handleTextSourceScript() calls the shared parser first.
  * It rebuilds the legacy dispatch input from valid tokens only.
  * Valid tokens retain source order and duplicates.
  * The existing sequential if/else handler and generated stat/proficiency loops
    perform world mutation. The catalog is metadata, not a second mutator.
  * A non-native valid token instead routes, in the same sequence, through the
    callback stored by registerScriptTagExtension(). The callback sees the real
    parsed Token and the live source Entity via an opaque lightweight context.
  * Map-generation-only extensions dispatch in parseScriptInMapGeneration()
    only after a valid @script marker is confirmed. They are then removed from
    the later runtime stream, preventing duplicate callback execution.
  * Extension callbacks cannot mutate the registry while validation/dispatch is
    active. Exceptions are caught at the registry boundary and become errors.
  * textSourceProcessScriptTag() remains the legacy packed-value decoder. The
    @setvar= name/integer decoder is shared with the tester.

2.7 Zed tester path

  * The tester uses ScriptTextParser and the same resource resolver as gameplay.
  * Validate / Parse uses parseTextSourceScript().
  * The editable script buffer is the sole tester working copy; validation and
    Run Test synchronize from that buffer.
  * Run Test invokes TestSession. Directives are reported, @setvar= changes only
    disposable TestSession variables, and all gameplay mutations are blocked.
  * Run Test also requires a valid @script marker. Without one, it reports that
    gameplay would keep the sprite in message mode and performs no disposable
    state transition.
  * The selected Text Source contributes source X/Y, playableFloor,
    authoredMapLayer, local z, and spatialRevision independently.
  * Zed has no running MapInstance; this is displayed explicitly instead of
    inventing one.
  * The Library page consumes the same registry generation as gameplay. A load,
    unload, restore, or removal invalidates selection/category caches and the UI
    rebuilds from the current unified view.


3. GRAMMAR CHARACTERIZATION

3.1 Case and delimiters

  * Tags and enumerated values are case-sensitive.
  * Tags require no whitespace between name, operator, and value.
  * ASCII space separates tags. Multiple spaces are harmless.
  * A second '@' also begins the next token, even with no intervening space.
  * There is no quote, escape, or script-comment syntax.
  * Non-'@' text is ignored by the command scanner.

3.2 Operators

  * Most valued literals include '=' in their canonical spelling.
  * The generated stat and proficiency families accept '=' and '+'.
  * No other '+' alias/family was found.

3.3 Integers and ranges

  * Signed decimal integers are accepted by the shared parser.
  * A one-dimensional range is A-B. Negative endpoints are represented without
    whitespace, for example -2--1. The legacy decoder was corrected to avoid
    mistaking the leading sign for a range separator.
  * A map range is X,Y or X1-X2,Y1-Y2. Many map-range commands also accept all.
  * Map coordinates are offset by mapGenerationRoomX/Y, clamped to current map
    bounds, and packed into four 8-bit fields by the legacy decoder.
  * Map coordinates above 255 cannot be represented by that packed contract.
  * Effect assignment uses effect-or-range;duration-or-range.
  * Explode uses context-dependent forms: attached sprite integer, or X,Y with
    optional ;sprite when nonattached.

3.4 Sequence and duplicates

  * Tokens execute in source order.
  * Duplicate tokens are retained.
  * Repeated @setvar= for the same key leaves the final value.
  * @reattachto= changes which entities later attached commands see.
  * When ordering must span simulation ticks, multiple Text Sources and Message
    Delay remain the runtime mechanism; the language has no wait statement.

3.5 Malformed/unknown behavior after this pass

  * Parser: Error diagnostic and Token::valid=false.
  * Tester Validate: fails; Run Test stops before state changes.
  * Gameplay: skips only invalid tokens and dispatches remaining valid tokens.
  * Unknown guide-only tags are not silently treated as verified library items.


4. MACHINE-READABLE CATALOG DESIGN

The lightweight public metadata types live in text_source_script.hpp. Native
data lives in text_source_script_catalog.cpp so every engine/editor translation
unit does not parse a giant initializer. text_source_script_registry.cpp owns
extension strings deeply and materializes one unified view. Every
ScriptTagDefinition records:

  canonical spelling; display syntax; insertion template; category; aliases;
  pattern-family status; value kind/count/separators/domain; attachment mode;
  targets; scope; map-range/all support; persistent-state flag; authority;
  editor safety; default behavior; description; minimal valid example; invalid
  example; caveats; source location; verification depth; manual requirement;
  verification method; precise dispatch evidence; origin kind/display name;
  stable source identifier; source version when supplied; availability/detail;
  dispatch phase; optional private-schema validator; and extension callback.

The parser directly consumes the unified registry. The editor library
introspects it. The test suite walks every definition. There is no independent
tester tag list and no second S.A.M catalog. Because the native world mutator is
still an if/else dispatcher, a bidirectional source consistency test compares
active native runtime spellings against normalized native catalog spellings and
checks every dispatchEvidence fragment. Commented-out @addtomonster= is stripped
before this comparison. Registered extensions are instead checked through the
actual register/parse/validate/dispatch/unload/restore path.

Registry collision policy:

  * Exact canonical collisions, alias collisions, and prefix ambiguities are
    rejected. The parser is prefix-based, so allowing prefix ambiguity would
    make load order an undocumented precedence rule.
  * Native literal commands and all 44 concrete generated-family prefixes win;
    an extension cannot replace them.
  * Two extensions cannot claim the same/overlapping spelling, even from the
    same owner while both are live.
  * Extension presentation/index order is stableSourceId then canonical command,
    independent of call order. Collision acceptance is explicit first-success:
    the already registered owner remains and the later registration receives a
    failure. A future S.A.M adapter must invoke registration in S.A.M's existing
    dependency/namespace deterministic order on every peer.
  * A retained unavailable definition can be restored only by the same stable
    source ID and canonical spelling. A different owner cannot take it over.
  * Aliases are exact prefixes supplied as metadata and route to the same
    canonical callback. They are not cosmetic library-only aliases.


5. COMPLETE CURRENT TAG INVENTORY

5.1 Structure, triggers, and attachment

@script
  Contract: no value; @attached.script is unsupported because map-generation
            recognition does not strip the execution-only prefix.
  Behavior: selects the script lifecycle rather than Text Source message mode.
  Default: recommended first, although legacy recognition searches the text.
  Verification: DISPATCH VERIFIED; MANUAL BEHAVIOR REQUIRED.

@triggerif=
  Values: always, attached#dies, attached#exists, attached#invisible,
          attached#visible, attached#interacted.
  Behavior: selects automatic triggering instead of circuit power.
  Caveat: attached#interacted currently acts only for attached bells. Prefixing
          the directive itself as @attached.triggerif= is unsupported.
  Verification: DISPATCH VERIFIED; MANUAL BEHAVIOR REQUIRED.

@attachto=
  Values: players, monsters, items, gold, bell, breakable, collider, or an exact
          current monstertypename.
  Behavior: one-time UID selection during map generation; source tile unless an
            @attachrange= is supplied.
  Unsupported values: summontrap and teleporter. @attached.attachto= is also
                      unsupported; setup directives are not execution targets.
  Verification: DISPATCH VERIFIED; MANUAL BEHAVIOR REQUIRED.

@attachrange=
  Values: map range or all.
  Behavior: supplies selection coordinates to @attachto=/@reattachto=.
  Caveat: packed 8-bit coordinates after offset/clamp; @attached.attachrange=
          is unsupported.
  Verification: DISPATCH VERIFIED; MANUAL BEHAVIOR REQUIRED.

@reattachto=
  Values/targets: same resolver domain as @attachto=.
  Behavior: clears and rebuilds attachments at its execution position.
  Safety: BLOCKED IN EDITOR TEST MODE.
  Verification: DISPATCH VERIFIED; MANUAL BEHAVIOR REQUIRED.

7. TESTER SECOND-PASS REVIEW

7.1 State before this review

The already-implemented tester was preserved. It already:

  * opened from a new Zed Scripts menu;
  * loaded $resource entries through ScriptTextParser;
  * used a shared parseTextSourceScript front-end;
  * displayed a read-only context snapshot and diagnostics;
  * blocked live-world operations; and
  * executed @setvar= only in disposable state.

7.2 Problems found

  * The parser carried a private hardcoded command surface, separate from the
    future library it needed to power.
  * Argument types were too broad. Examples include treating @damage= like a map
    range, accepting unbounded proficiency indices, and insufficiently checking
    effect/explosion shapes.
  * @setvar= decoding was duplicated between gameplay and tester.
  * Gameplay logged shared parser errors but still sent malformed tokens to the
    legacy stoi dispatcher.
  * The tester showed only a loaded preview, not an editable working script.
  * There was no searchable catalog, filtering, details, insertion, or recipes.
  * No registry-wide drift test covered all active tags or pattern expansions.
  * Several @script scans leaked across playable floors/MapInstances.
  * @copyNPC's nonattached connected-player loop stopped at the first disconnected
    slot, a four-player-era shape incompatible with sparse 15-player sessions.
  * The generated-family parser accepted leading-zero proficiency spellings that
    the runtime-generated dispatch names could never match.
  * Run Test allowed disposable @setvar= execution without @script even though a
    newly authored Text Source would remain in message mode.
  * A failed $resource lookup cleared the editable working copy, and an overlong
    generic Zed clipboard paste was not guaranteed to leave a trailing NUL.

7.3 Corrections made

  * Added the shared metadata catalog and strict per-kind value contracts.
  * Added canonical/catalog identity to parsed tokens.
  * Added Token::valid and filtered malformed/unknown tokens before live legacy
    dispatch while preserving valid token order and duplicates.
  * Shared @setvar= decoding between runtime and TestSession.
  * Added editable 16 KiB working copy and explicit append/backspace-at-end UI.
  * Added Tags/Recipes library modes, search, categories, verification filters,
    selection details, source/method/caveat display, and insert actions.
  * Added focused Playable-Z/MapInstance filters and spatial spawn contexts.
  * Prevented item-transfer commands from deleting world records when no target,
    slot, pickup, or S.A.M-backed conversion succeeds.
  * Required exact generated proficiency spellings and gated sandbox execution on
    a valid @script marker.
  * Preserved the current working copy after resource lookup failure, marked a
    truncated resource as edited, and made clipboard paste termination explicit.
  * Rewrote the test as a data-driven full catalog characterization suite.

7.4 Honest runtime sharing boundary

The tester does not instantiate a fake monster/map/player interpreter and does
not call live TextSourceScript::handleTextSourceScript() inside the editor. Such
a call would mutate the authored/current world and would not be a disposable
test. The shared portions are tokenization, recognition, value validation,
canonical resolution, resource resolution, metadata, and @setvar= decoding.
Every other command is proven to an active dispatcher seam and marked Dispatch
Verified, then blocked with a reason. This is intentionally not described as a
behavior execution test.

13. S.A.M. INTERACTION

The current tree marker is S.A.M Framework 2.1.0.

Actual registration/lifecycle audit:

  * All current src/sam C/C++ headers and implementations were searched for
    TextSourceLanguage, Text Source, @script, command/keyword registration,
    callback command registries, aliases, and namespace command surfaces.
  * SAMModManifest contains dependencies, classes, items, patches, monsters,
    spells, effects, races, sounds, recipes, plugins, models, images, and rooms.
    It has no Text Source command/keyword/alias/argument metadata.
  * SAMLoader rebuilds content registries on load and creates fresh Lua and
    QuickJS/TypeScript VMs. It loads class/item sibling scripts and mod-level
    main.ts/main.js/main.lua files defining on_event and/or on_tick.
  * sam_register_hook() in Lua and JavaScript registers a namespaced custom
    EVENT name in g_customHooks. It does not register a Text Source parser
    spelling or handler. Those vectors currently allow repeated event names;
    that behavior is unrelated to Text Source command collision policy.
  * Plugin paths may be declared, but SAMLoader explicitly states native plugin
    loading is not implemented. A manifest callback name therefore cannot be
    treated as an executable Text Source command.
  * S.A.M runtime VMs are excluded from the editor build. SAMFoundation still
    scans shared manifest content for editor-visible data, but there is no
    editor or game Text Source registration call to consume.
  * SAMLoader::unload clears its content registries and scripting VMs. Because
    there are zero current S.A.M Text Source registrations, no current unload
    hook into the unified registry is required or fabricated.

Current command result:

  S.A.M. Framework commands = 0.
  S.A.M.-mod commands = 0.
  Aliases/families/conditions/actions/selectors registered through S.A.M = 0.

This zero is a positive source finding, not an assumption. The automated test
recursively checks current src/sam C/C++ files for @script literals or calls to
registerScriptTagExtension(). A future source addition therefore makes the
consistency test fail until its actual lifecycle is adapted and catalogued.

Unified future registration seam:

  * registerScriptTagExtension() deeply copies metadata supplied by a S.A.M
    adapter; temporary manifest strings cannot dangle.
  * Required origin metadata is S.A.M Framework or S.A.M Mod plus display name
    and stable source ID. Source version is retained when actually supplied.
  * Exact commands and exact aliases feed the same parser/library/runtime view.
    A RegisteredExtension argument kind permits a private validator without
    adding S.A.M schema types to the public header.
  * Available entries require a live dispatch callback. Registration alone does
    not change VerificationLevel; an uncharacterized entry should be marked
    NeedsVerification rather than falsely promoted.
  * dispatchPhase separates map-generation setup from runtime action. A
    map-generation callback runs only after a valid @script marker and is not
    dispatched again at runtime.
  * markScriptTagSourceUnavailable() retains copied metadata, marks it missing,
    and clears validator/dispatch function pointers before a mod can unload.
    Re-registration by the same stable source restores the entry. Full removal
    is also available when retained metadata is not desired.
  * The registry is a main-thread lifecycle facility. It is deliberately not
    synchronized, and mutation is refused while an extension validator or
    dispatch callback is active.

This is a clean adapter target, not a claim that S.A.M. 2.1.0 already calls it.
When a later S.A.M version adds a real registration API/manifest field, its load
and unload sites must feed this seam in both gameplay and editor registration
lifecycles; the new source-surface test will force that work.

Text Source language findings:

  * There is no stable-ID @script literal.
  * There is no direct numeric item-ID @script argument in this tag set.
  * Item commands operate on already-existing attached/world item entities.
  * newItemFromEntity() accepts arbitrary valid runtime item IDs rather than
    clamping to NUMITEMS, and for a custom runtime ID requires the S.A.M registry
    to resolve a nonempty stable ID.
  * An unavailable or numeric-only custom item is refused; it is not substituted
    with an unrelated vanilla item. The reviewed @script transfer paths now keep
    the source world entity when that refusal means no transfer succeeded.
  * The transfer commands then use the normal Item/inventory/chest/equipment
    paths, so loaded S.A.M definitions can flow through those paths.

Limitations:

  * A script cannot name stable_id directly.
  * A missing-mod preserved record cannot be materialized by these world-item
    transfer commands until current runtime registration exists.
  * Custom equipment-slot metadata and multiplayer registry agreement need live
    tests.
  * No stable-ID command syntax, custom entity spawn tag, custom monster tag, or
    custom selector was invented from similarly named Lua/JS host APIs.
  * Retained unavailable command metadata is in-memory lifecycle state, not a
    new persistent editor cache. The current S.A.M manifest has no authoritative
    command schema from which to reconstruct such a cache after process restart.
  * No S.A.M header or JSON header was introduced into the lightweight Text
    Source public interface.

15. SECURITY, TRUST, AND ERROR HANDLING

  * Catalog entries do not expose filesystem, shell, process, save, Steam, or raw
    network operations.
  * @nextlevel= is the broadest global state transition and is blocked in Zed.
  * Every gameplay mutation is blocked in Zed, including ostensibly reversible
    map changes.
  * Resource keys are looked up in ScriptTextParser's loaded entries; the tester
    does not execute scripts from arbitrary file paths.
  * Integer parsing is full-consumption and range-checked against int.
  * Invalid tokens are filtered before legacy stoi dispatch.
  * Failed resource lookup preserves the current editable working copy.
  * Zed clipboard pastes are explicitly NUL-terminated at the configured input
    bound; insertion helpers remain atomic on capacity failure.
  * Catalog-defined semantic domains such as live monster names and class bounds
    may still be resolved by the active runtime handler because the standalone
    parser intentionally has no dependency on engine registries.
  * Untrusted clients do not authoritatively execute Entity::actTextSource().
  * The registration API is an internal C++ adapter seam; current Lua/JS scripts
    cannot call it. It does not turn sam_register_hook names or manifest strings
    into native function pointers.
  * Extension metadata is deep-copied, required fields are validated, private
    schemas require a validator, and executable definitions require a callback.
  * Callback/validator exceptions are contained and reported. Registry mutation
    from inside either callback is refused, preventing index/pointer invalidation
    while a parsed token stream is executing.
  * A future adapter callback has the same trust/authority as that adapter's
    engine bridge; this registry does not grant Lua/JS new filesystem, shell,
    network, or raw memory capabilities.

19. KNOWN LIMITATIONS AND DEFERRED CONCERNS

  * Registry registration/collision validation is linear in existing definitions
    and parsing is linear in definitions/aliases per token. Registration is a
    mod-load operation, the unified vector is generation-cached, and the current
    live size is 37, so no runtime regression was observed. A future ecosystem
    with hundreds/thousands of commands should profile an indexed lookup that
    preserves exact prefix-collision semantics.
  * Native world handlers remain legacy if/else mutation code. Extensions have
    a callable registry seam, but moving all native handlers behind it would be a
    larger compatibility-sensitive scripting redesign and remains out of scope.
  * Runtime semantic registries (monster names, classes, effect meanings) are not
    linked into the lightweight editor parser. Their word/integer shape and active
    dispatch are verified; live availability remains runtime-dependent.
  * Map range packing is 8-bit per endpoint.
  * Inline Text Source physical storage is much smaller than the tester's 16 KiB
    resource-oriented buffer.
  * Generic Zed input supports end editing, not arbitrary caret insertion, in
    this window.
  * No unsupported/historical tab is exposed as insertable content; such entries
    remain in this audit only, by design.
  * The native catalog has zero proven aliases. Extension aliases must be live
    registered spellings and are parser/dispatch tested; cosmetic aliases remain
    forbidden.
  * Current S.A.M. 2.1.0 has no command registration lifecycle, so dynamic
    S.A.M entries cannot be demonstrated with real shipped content. The test
    fixture proves the shared seam only and is removed immediately.
  * Retained missing-mod metadata lasts for the current process/load lifecycle.
    There is no fabricated disk cache because current manifests expose no
    authoritative command schema.
  * Extension command families with arbitrary matchers are not exposed by the
    current S.A.M and are not invented. Exact registered commands, exact aliases,
    and private argument validators are supported.
  * registerScriptTagExtension() is a source-level C++ adapter contract, not a
    stable cross-compiler DLL ABI. If S.A.M later implements native plugin
    loading, a versioned C ABI/owned bridge must sit in front of it rather than
    exporting std::string and function-pointer contracts directly to arbitrary
    binaries.
  * Manual GUI confirmation is still required; successful editor compilation is
    not visual acceptance.
  * The authorized Text Source Script Tester work is present. Z4 was not started.

21. FINAL INTEGRATION DECISIONS

  1. Current C++ remains language authority; guide remains secondary.
  2. One unified native/extension registry powers parsing, library metadata,
     examples, tests, and extension dispatch; no unrelated S.A.M catalog exists.
  3. Native legacy world handlers are retained; registered extension callbacks
     join their real token stream without creating a fake second language.
  4. Invalid tokens are filtered; valid neighbors still execute in order.
  5. Only disposable @setvar= executes in editor test mode.
  6. Verification depth is explicit and manual needs are never hidden.
  7. Guide-only @findanytarget= and unavailable variants are not insertable.
  8. Existing guide/current semantic conflicts are documented, not silently
     changed where old map compatibility needs a deliberate decision.
  9. @script-specific Playable-Z/MapInstance leaks are fixed narrowly.
 10. No network packets, Playable-Z model, Divergent Paths model, Text Source
     language, or S.A.M identity syntax was redesigned.
 11. Current S.A.M. 2.1.0 contributes exactly zero Text Source commands. Its
     Lua/JS/TS APIs and namespaced event hooks remain separate and are not
     misrepresented in the Library.
 12. Native/extension exact, alias, prefix, and generated-family collisions are
     rejected. Stable owner identity is required to restore retained metadata.
 13. Origin and availability are independent of verification depth; registration
     never implies Behavior or Manual Game Test verification.
