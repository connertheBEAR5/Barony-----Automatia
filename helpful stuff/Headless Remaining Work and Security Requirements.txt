BARONY AUTOMATIA HEADLESS SERVER: REMAINING WORK AND SECURITY REQUIREMENTS
=========================================================================

This file documents the boundary between the functional LAN dedicated server
and features that require deeper engine or protocol changes.

1. SECURE PASSWORD AUTHENTICATION
---------------------------------
Do not transmit or log a plaintext password. Add a versioned connection
handshake using a server nonce, a memory-hard password derivation function,
an authenticated response, constant-time comparison, retry limits, and generic
failure messages. Authentication must finish before allocating player state.

2. PUBLIC SERVER LISTING
------------------------
Public mode needs explicit Steam/EOS/platform lobby registration, server
identity, removal on shutdown, stale-listing recovery, and abuse controls.
Opening a UDP socket is not public-listing support.

3. LATE JOIN REMAINING ACCEPTANCE AND SECURITY
----------------------------------------------
The explicit direct-connect LAN path now has a versioned, bounded authoritative
map-instance snapshot; per-chunk and whole-transfer checksums; reliable
begin/data/complete records; S.A.M. fingerprint validation; and a
ready/authorize/client-go barrier before live output. Bounded LJCB/LJCC/LJCE
incremental catch-up, LJAB aborts, 30-second progress timeouts, and per-slot
128-bit reconnect bearer identities are implemented. Contained direct-LAN
new-player probes pass the current snapshot/catch-up/start sequence, but this is
not a complete graphical two-client acceptance. Required remaining work includes
that real server/two-client run, a current token-matched returning-player run,
loss/reordering and timeout stress, malformed-client testing, Windows coverage,
and P2P transport integration. Public or password-protected late join must
remain unavailable until their authentication requirements are met. Reconnect
bearer tokens are session/save credentials, not platform account identity.

4. TRUE RENDERLESS STARTUP
--------------------------
Move simulation-required definitions out of texture/model/OpenGL loaders.
Only then may the hidden OpenGL context be removed. CI should run startup and a
short simulated session with no DISPLAY/Wayland server.

5. SAVE AND RESTART RECOVERY
----------------------------
The numeric-slot Linux LAN path writes multiplayer saves under
savegames/host/ and uses the versioned schema-v3 persistent-world companion,
matching character/world transaction IDs, atomic temporary write plus rename,
stable custom-item identity, graceful shutdown save, and fail-closed validation.
The headless process-only slot 0 is not serialized as a player. Player and
dynamic-entity spatial records preserve map instance, playable floor, authored
structural layer, and local Z separately. A single-map FMOD
start/save/restart/resave acceptance cycle passes. The contained cross-map party
process test now covers two divergent simulated
clients, SAMF, save/shutdown/restart, and durable Party ID hydration. Remaining
work includes the equivalent real-client divergent recovery, unknown-item
removal/rehydration acceptance, corrupted-save fixtures, clean-shutdown/crash
markers, migration coverage, and Windows runtime verification.

Steam note: --nosteam skips SteamAPI and therefore disables Steam ownership and
DLC checks rather than emulating them. DLC remains locked. Use the Steam
client's supported Offline Mode and launch without --nosteam when Steam
entitlement is required. No server code may parse private Steam cache files or
fabricate an offline entitlement.

6. TESTING
----------
Test pre-game join, disconnect, autostart, terminal start/shutdown, invalid
ports, occupied ports, malformed packets, catalog mismatch, long runtimes, and
vanilla graphical startup. Unsupported options must fail closed.

CURRENT VALIDATION SNAPSHOT (2026-08-28)
----------------------------------------
The primary configured Steamworks-enabled 15-player build is `build`; use
`cmake --build build -j6` on the current host. The latest source validation
passed that build, all 13 CTest targets, the Stage 4D/Z3 Playable-Z
characterization, and the diff check. The Linux single-map headless cycle,
contained divergent two-client party/SAMF/save/restart run, and contained
direct-LAN new-player late-join probe are runtime evidence already recorded.
The exact one-headless plus two-real-graphical-client divergent/restart run,
token-matched returning reconnect, real S.A.M. mod content, and Windows
headless acceptance remain open.

Playable-Z persistence keeps map instance, playable floor, authored structural
layer, and local Z separate. Legacy ceiling-model visual-light compatibility is
a client renderer rule and does not alter headless save records, floor scoping,
or map classification.
