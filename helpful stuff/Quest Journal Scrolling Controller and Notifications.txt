QUEST JOURNAL SCROLLING, CONTROLLER, AND NOTIFICATIONS
========================================================

Scrolling
---------
The journal is no longer limited to the first eight quests.

It keeps eight visible rows, but supports an unlimited category list.
The selected quest remains visible as the scroll offset changes.

Controls:
- Mouse wheel: previous/next quest
- Up/Down: previous/next quest
- Controller D-pad Up/Down: previous/next quest

A page indicator shows the visible range, for example:

    9-16 of 24

Tabs
----
- Left/Right changes category.
- Controller D-pad Left/Right changes category.
- Controller LB/RB also changes category.

Closing
-------
- J
- Escape
- Controller B
- Mouse close button

Persistent runtime selection
----------------------------
Each player retains:
- selected tab,
- selected quest,
- list scroll position

These remain remembered while the process is running.

Quest-update notifications
--------------------------
The journal records a baseline snapshot of discovered quests.

Later changes to:
- quest status,
- quest stage,
- accepted/completed/failed state,
- objective completion

produce:

    Quest updated: <quest title>

The initial baseline does not produce notification spam.

Current limitations
-------------------
- Notification text uses the normal inventory message channel.
- Notifications are runtime/session only.
- The journal is still an overlay rather than a native module button.
