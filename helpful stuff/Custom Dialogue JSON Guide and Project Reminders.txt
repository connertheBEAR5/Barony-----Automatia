BARONY AUTOMATIA CUSTOM DIALOGUE JSON GUIDE
AND PROJECT REMINDERS
============================================================

PER-PLAYER QUEST FOUNDATION
---------------------------
Quest state is separate for every multiplayer player slot.
A completed quest is one-time per player: Player A completing Quest A
does not stop Player C from accepting and completing it, but neither
player can accept it again after their own completion.

Current key: player_<slot>:<normalized quest ID>
Limitations: session-only; slot identity; repeatable resets, party/world
scope, save serialization, and permanent character identity come later.

JSON ROOT
---------
Runtime file: build/dialogue/test.json
Required shape:
{
  "version": 1,
  "quest_id": "torch_for_the_stranger",
  "start_node": 0,
  "nodes": []
}

NODE FIELDS
-----------
id: unique integer node ID
text: NPC text
next: next node; self-reference is terminal
choices: selectable replies
condition: optional redirect
 action: optional one-time consequence

CHOICE FIELDS
-------------
id: stable choice ID
text: displayed reply
next: destination node
once: remember as used
condition: visibility requirement
action: host-authoritative consequences

SUPPORTED CONDITIONS
--------------------
has_item, has_gold, quest_started, quest_accepted, quest_completed,
quest_failed, quest_stage, world_flag, npc_flag, world_variable,
npc_variable, node_seen
Comparisons: equals, not_equals, at_least, at_most
Quest conditions use the interacting player's personal quest state.

SUPPORTED ACTIONS
-----------------
quest_start, quest_accept, quest_stage, quest_complete, quest_fail,
reward_gold, remove_gold, reward_item, remove_item, set_world_flag,
set_npc_flag, set_world_variable, add_world_variable,
set_npc_variable, add_npc_variable

MULTIPLAYER
-----------
The host validates choices and applies quests, rewards, payments,
variables, flags, and dialogue progression. Remote clients only receive
choices and send a selection.
