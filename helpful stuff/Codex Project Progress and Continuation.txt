FAILURES FOUND AND FIXED
========================

* Returning late-join placement was consumed during preparation, before the
  client completed snapshot authorization. It now remains pending until a
  successful LJGO authorization/start sequence.
* Runtime returning JOIN validation compared against transient load flags that
  are cleared after startup. It now compares against the running game and lobby
  keys.
* The live probe assumed only the short HELO roster layout. It now accepts both
  valid lobby and saved-equipment layouts and acknowledges the chunk bootstrap.
* Headless recovery could lose a disconnected saved slot or give it to a new
  joiner. Pending saved placements are retained and reserved.
* Save restoration could continue applying effects or followers through the
  wrong global map if a requested instance activation failed. Those operations
  now fail locally with a focused diagnostic and skip that player.
* A retired legacy map identity retained aliases to global path/shop buffers
  after ownership moved to a newly bound identity. Those aliases are cleared at
  the rebind boundary, preventing a later stale-pointer/double-free hazard.
* Custom-transition packet construction did not explicitly bound the map name
  against the reliable packet payload. Oversized names are now rejected before
  transition mutation.
* A headless/FMOD title-music fade could dereference an unavailable sound during
  no-sound startup. The title transition now validates the music state first.
* Map-local updates produced between snapshot capture and spawn authorization
  were discarded. They are now retained in a bounded catch-up transaction and
  replayed before live traffic.
* Incomplete or corrupt snapshot transfers had no explicit timeout/abort
  lifecycle and could retain staged documents or chunk memory. Both peers now
  abort, validate the abort source, clean staged state, and release buffers.
* Returning identity depended only on slot and ordinary save metadata. LAN
  reconnect now also requires a server-issued per-slot bearer token saved by
  both peers; missing or mismatched identities fail closed.
* Headless slot 0 appeared as a rendered player and occupied map membership.
  Dedicated startup now retains no slot-0 entity and advertises no host player.
* Headless startup deleted or persisted-away unused Player Starts, preventing
  new late joiners from spawning. Player Starts are now retained invisibly and
  excluded/healed from persistent entity-removal records.
* Running late-join servers were marked locked in LAN discovery, and empty
  dedicated servers were filtered from the browser. Dedicated discovery now
  identifies those servers explicitly and leaves late-join sessions joinable.
* Static light entities could receive synchronized initialization flags before
  owning their client-local light object. Their behaviors now reconstruct the
  missing local light using the synchronized steady/flicker state.

  list included player 2 UID 5. `test.lmp` legitimately reused UID 5 for that
  same player, and the `ENTU` handler silently rejected the destination entity
  because the tombstone had no map-instance context. The following `BDYI` and
  `ENTB` packets then had no parent entity to update. This explains the exact
  order-dependent, one-way visibility failure.

Failures fixed
--------------

* Removed-entity tombstones now retain their source map-instance key and
  revision. They apply only while that exact instance revision is active.
  On the first authoritative entity update after a map-instance change, stale
  source tombstones are cleared and a focused diagnostic reports the old and
  new instance identities. Ordinary `ENTD` processing re-scopes tombstones to
  the active instance before recording a removal.
* Reliable map-local retry scoping from the preceding fix remains in place, so
  an old reliable entity update is discarded when its recipient has changed
  map key or revision. Retries now also require the recipient's late-join
  transaction to permit live simulation, preventing a same-instance retry
  from bypassing snapshot/catch-up gating.
* Loading a first-time destination can insert into the `WorldState` instance
  registry and rehash its storage. The transition path no longer retains a
  potentially invalid `MapInstance*`; it reacquires the source instance and
  player entity by stable key after destination loading.
* Player `BDYI` packets were four bytes too short. A 29-child player model
  writes 28 child UIDs and requires 120 bytes; the old shared monster formula
  advertised only 116 bytes. Player and monster packet lengths are now
  calculated from their different skipped-child counts.
* Client `BDYI` and `ENTB` handlers now reject truncated packets before reading
  or mutating state. Invalid/null bodypart nodes are guarded on both send and
  receive paths.
* Reinitializing a live destination map on each arrival was not used. Such a
  reload could recreate fixtures, reset transient combat/projectile state, and
  conflict with persistence; the defect was an entity-identity tombstone leak.

2026-08-22 PLAYABLE-Z LIGHT/FALL/PERSISTENCE FOLLOW-UP
======================================================

The source-of-truth coordinate model remains unchanged:

* authoredMapLayer is physical structural height.
* playableFloor is gameplay/spatial membership.
* Entity::z is local model/animation elevation.
* world Z is local Z plus mapLayerWorldZ(authoredMapLayer).

Upper authored lights previously traced horizontal shadows against their own
floor tile instead of the obstacle layer above it. They now use authored layer
N + OBSTACLELAYER. On maps with a real derived authored-floor stack, dynamic
lights also contribute to other structural light slices using 3D attenuation;
each crossed authored plane must be open. Legacy one-floor and explicit-FLOR
light buffers do not receive this multi-slice expansion.

Upper-to-lower fall placement now validates the player's full collision
footprint. It preserves the ledge X/Y when safe and otherwise clamps the landing
inside the lower tile with wall clearance before the existing authoritative
PZTR transaction. Runtime characterization covers both a wall-adjacent clamp
(31.50 to 27.95 for size 4) and an unchanged clear-adjacent landing.

Player character metadata, shared-world player records, and divergent return
history now preserve authoredMapLayer separately from playableFloor and local
Z. Spatial save validation covers persistent dynamic collections and unique
map-instance/floor/X/Y/geometry-layer tile records. Old records without the
authored field remain valid and migrate only through explicit derived-stack
semantics. Headless saves remain in savegames/host/, share a transaction ID
with their companion, use atomic validation/replacement, and omit process slot
0.
