QUEST JOURNAL BACKEND AND CURRENT UI STATUS
===========================================

Purpose
-------
This document originally described the data-layer milestone. The inventory
quest-journal UI now exists and consumes this backend. It provides the quest
list, objectives, tracking information, controller navigation, camera/input
locking, and inventory-safe close behavior. The API and entry semantics below
remain the backend contract.

Public API
----------
getCustomDialogueQuestJournalEntries(player, entries)

The function returns journal-ready entries for the selected player.

Quest entry data
----------------
Each entry contains:

- dialogue ID
- quest ID
- title
- summary
- general objective
- completion text
- failure text
- scope
- repeatable flag
- current player-specific stage
- accepted/completed/failed flags
- calculated journal status
- objective list

Journal statuses
----------------
Active
Completed
Failed

Unstarted quests are omitted.

Objective data
--------------
Each objective contains:

- objective ID
- active text
- completed text
- authored stage
- optional flag
- player-specific completion flag
- visibility flag

An objective is visible when:

- its authored stage is at or below the player's current quest stage, or
- the player already completed it

Sorting
-------
Quest entries sort in this order:

1. Active
2. Completed
3. Failed

Entries within a status sort by title.

Objectives sort by:

1. Stage
2. Required before optional
3. Text

Discovery limitation
--------------------
The backend enumerates valid custom-dialogue definitions already loaded
into the active process. Therefore a quest becomes journal-discoverable
after its dialogue definition has been loaded, normally when its NPC is
first interacted with.

A future quest manifest can preload every authored quest definition.

Persistence and scope status (2026-08-23)
-----------------------------------------
Quest and dialogue state is serialized through the Automatia companion save;
dedicated per-character saves export/import the selected player's story state.
Player scope is the only quest ownership mode currently executed by the
dialogue runtime. Authored party/world scope values are accepted by the editor
but load safely as player scope until real party/world ownership is implemented.
